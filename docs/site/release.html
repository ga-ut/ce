Release, Verification, and Rollback

Use this page before tagging a release or publishing the package. It separates runtime validation, package checks, and post-release safety work.

CI gate

Tag a release only when lint + test + build pass.

Pre-publish verification

  1. bun install
  2. bun run lint
  3. bun run test
  4. bun run build
  5. bun run test:events
  6. bun run docs:build
  7. bun run docs:validate
  8. bun run pack:check

Publish

Run the Publish npm package GitHub workflow from the matching vX.Y.Z tag. The workflow uses Bun for install, validation, build, and bun publish --access public. It exchanges the GitHub Actions OIDC token for a short-lived npm token, passes it to Bun through NPM_CONFIG_TOKEN, and does not require a long-lived npm secret. Organization policy can override access mode.

Initial publish checklist for v0.1.0

  1. Confirm bun pm view @ga-ut/ce version does not find an existing published package.
  2. Use named web-runtime imports such as import { define, html, signal } from "@ga-ut/ce/web";.
  3. Confirm consumers do not use legacy object definitions.
  4. Use ce-cli build --entry ./src/main.js --out ./dist --css ./src/ce.css when a CE app is built without an external bundler.
  5. Publish from a matching v0.1.0 tag only.

Post-release smoke test

  • Route transitions
  • State updates
  • Event handling
  • App build through ce-cli
  • Published Pages status board timestamp

Rollback safety

If an issue is found, publish an immediate patch release with the fix and keep the rollback playbook in the release PR.
