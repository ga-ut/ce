Roadmap

Roadmap decisions are evaluated against runtime size, custom element compatibility, and the validation gates required before release.

Current focus

The current direction is to make function components, signals, derived values, explicit state matching, and the playground examples feel coherent as one API.

Compatibility rules

Runtime changes should preserve existing custom element behavior unless a major version explicitly documents the migration. New helpers should be optional and additive.

Documentation rules

Docs pages should explain the behavior directly on the page. Navigation and table-of-contents links help movement, but they should not replace the explanation.

Release readiness

A roadmap item is not ready to publish until source validation, event behavior tests, docs validation, and package build checks match the files changed.

CE docs describe the runtime surface, component model, release gates, and playground examples in-place.
