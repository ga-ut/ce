CE documentation

Build custom elements with local state, scoped DOM, and small runtime primitives.

CE is organized around named function components, signal-driven updates, explicit render states, and optional routing. This page explains the working model directly.

Component model

A component is a named function. The function name becomes the custom element tag, and the function body owns props, signals, derived values, lifecycle cleanup, and event handlers.

import { define, html, signal, derived } from "@ga-ut/ce/web";

define(function UserCounter({ props, lifecycle }) {
  const count = signal(props.initial ?? 0);
  const doubled = derived(() => count() * 2);

  lifecycle.cleanup(() => {
    // clear timers, listeners, or requests here
  });

  return html`
    <button onclick=${() => count.update((value) => value + 1)}>
      ${count} / ${doubled}
    </button>
  `;
}, {
  props: {
    initial: Number
  }
});

Runtime flow

Use this sequence when building a CE component. Each step is local to the component, so the final element stays portable.

  1. 01

    Declare the element boundary

    Name the component function and define typed props. The element tag is derived from the function name.

  2. 02

    Keep state close to setup

    Use signal for writable values and derived for computed values that depend on other signals.

  3. 03

    Render explicit branches

    Use match for idle, loading, success, and failure states instead of hiding control flow in nested conditionals.

  4. 04

    Clean up on disconnect

    Register cleanup for timers, observers, subscriptions, and in-flight request state through the lifecycle helper.

Core ideas

Named components

define(function MyCounter) registers my-counter without a separate tag string.

Signals first

signal and derived keep values close to the component setup code.

Explicit states

match keeps loading, success, and failure branches visible in render code.

Release rules

Source changes must pass lint, test, and build. Event behavior changes also run event tests. Documentation changes validate docs data and internal links.

  • Runtime gate

    npm run lint && npm test && npm run build protects source, playground, and package output.

  • Event gate

    npm run test:events covers custom event wiring, rerender handler stability, and docs page link policy.

  • Docs gate

    npm run docs:validate checks JSON data, markdown links, and internal documentation integrity.
