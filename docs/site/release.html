Release, Verification, and Rollback

CI gate

Tag a release only when lint + test + build pass.

Pre-publish verification

  1. bun install
  2. npm run lint
  3. npm run test
  4. npm run build
  5. npm run pack:check
  6. Confirm the document status board data was refreshed or explicitly marked as no-change.

Publish

Publish from packages/ce with npm publish --access public. Organization policy can override access mode.

Release notes

  • Breaking changes

  • Affected API list

Migration checklist for v2.0.0

  1. Replace all root imports with @ga-ut/ce/web for web runtime APIs.
  2. Confirm consumers no longer import CE or html from the package root.
  3. Run validation gates in this repository before publish.

Post-release smoke test

  • Route transitions
  • State updates
  • Event handling
  • Published Pages status board timestamp

Rollback safety

If an issue is found, publish an immediate patch release with the fix and keep the rollback playbook in the release PR.
